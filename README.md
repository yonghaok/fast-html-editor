# HTML 交互编辑器

> Point, edit, explain — turn visual frontend feedback into an AI-ready change plan.

HTML 交互编辑器是一款面向 **AI Coding 前端工作流**的 Chrome / Edge 扩展。你可以直接在正在运行的网页上选择元素、拖动布局、修改文字与图片、添加新文字框，并把全部操作导出成带定位信息的 AI 提示词和结构化改动清单。

它解决的不是“在浏览器里临时改 CSS”，而是一个更具体的问题：

**如何把“这里往左一点、这张图换掉、这段文字改短”准确交给 AI，让 AI 找到源码并完成修改。**

## 核心场景

传统 AI Coding 反馈通常依赖截图和自然语言：

```text
截取页面 → 用文字描述位置 → AI 猜测对应组件 → 多轮确认 → 修改源码
```

使用本扩展后：

```text
打开本地或测试页面 → 直接选择目标元素 → 交互式完成预期改动
→ 锁定位置添加说明 → 复制 AI 提示词 + 结构化清单
→ AI 定位组件、修改源码并验证
```

## 能力

- 持续选择模式：连续选择页面元素，不必反复开启工具。
- 交互式布局：拖动元素并按 `4 / 8 / 12 / 16px` 网格吸附。
- 内容编辑：修改现有文字，或在页面上添加新的文字框。
- 样式调整：修改宽度、高度、层级和圆角，隐藏或恢复元素。
- 图片编辑：替换或添加图片，调整图像尺寸、裁切方式与焦点位置。
- 精确注释：将说明绑定到页面 URL、元素 selector、语义上下文和元素内相对锚点。
- 操作撤销：撤销当前会话最近 12 步操作。
- AI 交付：复制包含执行规则的提示词与轻量 JSON，或下载包含图片数据的完整 JSON。
- 页面隔离：按完整 URL 保存记录，并支持 React、Vue 等 SPA 路由切换。

## 为什么适合 AI Coding

扩展导出的不是一张扁平截图，而是一份 AI 可以执行的前端修改协议：

- `page`：改动发生在哪个页面。
- `selector + context`：目标元素的结构定位和语义线索。
- `changes`：文字、样式、图片与相对位移。
- `creations`：需要新增的文字框等 HTML 元素。
- `annotations`：绑定目标元素和相对坐标的产品意图。

selector 只作为定位线索。导出的提示词会要求 AI 结合文字、最近标题与项目源码找到真正的组件，优先复用现有组件和设计规范，而不是把浏览器运行时样式直接复制进项目。

## 安装

1. 下载或克隆本仓库。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择仓库根目录。
6. 打开要编辑的 HTTP/HTTPS 页面，点击扩展图标。

快捷键：`Ctrl + Shift + E`；macOS 使用 `Command + Shift + E`。

## 使用流程

1. 开启“选择模式”，点击目标元素。
2. 在侧边面板调整文字、尺寸、层级、圆角、图片或显示状态。
3. 直接拖动元素，使用网格吸附确定位置。
4. 需要新增内容时点击“添加文字框”。
5. 添加注释并选择元素内的九宫格锚点。
6. 点击“复制 AI 提示词 + 清单”，粘贴给 Codex、Claude Code、Cursor 或其他 AI Coding 工具。

## 注释为何不会随滚动漂移

每条注释同时保存页面 URL、稳定 CSS selector、元素文字和 ARIA 信息、最近标题、元素内相对坐标，以及创建时元素矩形和视口尺寸。

页面滚动或普通响应式重排后，标记会根据目标元素重新定位，而不是锁死在屏幕像素坐标。

## 数据与权限

- `activeTab`：只在你主动点击扩展时访问当前页面。
- `scripting`：向当前页面注入交互编辑器。
- `storage / unlimitedStorage`：在浏览器本地保存改动和图片预览。
- `clipboardWrite`：复制 AI 提示词和改动清单。

数据默认只保存在 `chrome.storage.local`，不会自动上传到服务器。所有改动都是浏览器运行时预览，不会直接写入网站源码。

复制到剪贴板时会省略大体积图片 Data URL，避免复制失败；下载完整 JSON 时保留图片数据。

## 当前边界

- 扩展负责表达预期改动，不负责直接修改本地源码。
- selector 在页面大幅重构后可能失效，AI 应结合语义上下文重新定位组件。
- 替换图片用于视觉确认；正式项目仍应将图片放入项目资产或 CDN。
- 浏览器内部页面、扩展商店等受保护页面不能注入脚本。

## 项目结构

```text
interactive-html-editor/
├── manifest.json          # Manifest V3 配置
├── service-worker.js      # 扩展入口与页面注入
├── content.js             # 选择、编辑、标注、持久化与 AI 导出
├── editor.css             # 编辑器基础样式
├── text-editor.css        # 扩展控制区样式
└── README.md
```

## Roadmap

- 多元素选择与对齐/分布。
- 字体、颜色、间距等设计属性编辑。
- 改动清单导入与团队评审共享。
- 面向不同 AI Coding 工具的提示词适配器。
- 将 AI 修改结果与原始标注逐项验收。

## 开发

本项目不依赖构建工具。修改文件后，在扩展管理页点击“重新加载”，再刷新目标网页即可验证。

```bash
node --check content.js
node --check service-worker.js
```
